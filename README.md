# 轻衡 · Fitwise Local

本地优先的个人减脂、饮食、体重、运动、采购与食材库存管理应用。

## 当前实现

- 今日仪表盘：热量、蛋白质、纤维、体重趋势、主观状态与完成日。
- 饮食日记：三态营养值、营养覆盖率、标准菜谱和整锅消费比例。
- 0.3.3 食材库：新食物建档一次；按名称/品牌搜索、最近使用、收藏，选择数量后由 Rust 计算营养，再逐项确认记餐。
- 规格支持任意正参考数量的克、毫升、个、份、包装，保留 kJ/kcal 原始标签；只有用户确认的换算关系才允许跨单位使用。
- 食材营养规格不可变版本化；餐食保存版本、数量、换算关系及营养快照，修订资料不回改历史。保存资料不记餐、不扣库存；保留一次性手工餐食入口。
- 熟食批次：制作只扣一次原料，午晚餐按实际比例分别计入，剩余与浪费独立记录。
- 库存与采购：采购/收货分离、FEFO 扣减、临期和剩余成本。
- 0.3.4 采购：拼多多/淘宝/天猫/京东/抖音商城/美团/多多买菜及自定义渠道；下单时间、预计到货与实收日期分别保存。
- 包装采购支持“1 组 · 1 kg × 2 袋”等表达，确认规格后才换算为基础库存单位；订单金额、累计已付款和已到账退款分开，支持先用后付。
- 库存操作：实际重量与成本核对、分批收货、替换商品、取消余单、盘点、开封/到期日编辑、退货和腐坏；流水保留审计，失败重试不重复入库/扣减。
- 次日计划：三个候选方案、库存覆盖、缺货和后两日预演。
- 运动：手工记录、热量独立展示、来源指纹去重模型。
- 0.4.0 收件箱：手机上传或本地文件/文字导入，SQLite 同时保存接收记录、原件与缩略图，关页/重启后可继续处理；同图去重但保留各次备注和来源。
- 0.4.1 日常闭环：日报/饮食/运动/趋势共享日期；补记餐食需重新确认完整日；整锅分餐支持 0.01%；原件可独立另存。动态菜单明确是演示，AI/OCR 仍未接通。使用顺序见 DAILY_USAGE.md，阶段挑刺见 REVIEW_0.4.1.md。
- 0.4.4 菜谱体验修订：摘要去重、原料前移、详细规则与厨具折叠；关联旧配方保留兼容单位原量，不兼容时明确提示核对。无新增依赖，AI 尚未接通；详见 REVIEW_0.4.4.md。
- 0.4.3 受限账务纠错：误制作仅在快照完整且无后续操作时冲正，浪费修订／作废不退原料，历史配方可按原版制作或另存。schema 9、格式 4 不变；详见 REVIEW_0.4.3.md。
- 0.4.2 纠错与菜谱：餐食更正/作废保留证据，熟食事件与余量同事务更新，有效版本才进入统计；从食材库建自定义菜谱并固定营养版本，保存不扣库存。schema 9，持久化格式 4；详见 REVIEW_0.4.2.md。新版库不支持用旧程序直接降级。
- 采购表单按包装层级显示：普通“2 袋、每袋 1 千克”不再要求重复输入“内件数 1、内件包装袋”；组合装选择“组”才展开内包装。
- 图片按真实格式解码并限制像素；列表分页、懒加载缩略图，隐私预览支持手工框选并生成不可逆黑块派生图，不覆盖原件。
- 原件回收站可恢复，满 30 天后仍需主动确认永久清除；结构化接收记录保留。存储页分类统计、达到 2 GB 提醒，不自动删除证据。
- 趋势：完整日热量均值、七日体重移动平均。
- 本地持久化：浏览器开发模式使用 localStorage；Tauri 通过 Rust 事务仓库把状态拆分为 SQLite 单例和 16 类领域实体。
- SQLite schema v8、持久化格式 v4 保存仓库修订、内容哈希、命令回执及请求指纹；24 类原领域命令外，素材接收/遮挡/回收由独立 Rust 事务领域服务处理。附件清单随 JSON 导出，二进制原件不是 JSON 内容。
- 今日营养、库存余额、近七日均值和运动时长来自 Rust/SQLite 查询投影；JSON 导出从领域仓库生成。
- 升级前自动创建并验证本地安全快照，对账记录数量、营养、库存和内容哈希；数据库迁移失败会回滚。
- 桌面版首次使用不预填示例晨重或库存，83 kg 仅作起始参考；浏览器开发预览保留演示数据。
- 数据库加密备份：Argon2id 派生密钥、AES-256-GCM 认证加密、创建后立即恢复验证。
- 安全恢复：先暂存与复检，下次启动前保留当前数据库安全副本，失败自动回滚。
- AI 配置边界：可替换提供商、Windows 凭据存储、月度费用软上限与手工降级。
- 本地隐私预览：文本常见标识遮挡，图片人工框选像素遮挡；不自动保证所有隐私已经识别。使用获准安装的 [image 0.25](https://github.com/image-rs/image) 库（MIT/Apache-2.0），仅启用 PNG/JPEG/WebP。

真实 AI 网络请求、自动备份轮换、MCP/CLI 和截图视觉识别尚未开放，不会伪装成已配置服务。按用户最新要求，优先日常可用性，流式备份和副本轮换暂缓，未添加 aead-stream。现有 SQLite 备份会自然包含已入库附件；大库内存优化未完成。

素材入口仅限桌面版。图片最多 1600 万像素，单次最多 8 个附件、合计 20 MB。PDF 仅保存、不渲染；HEIC 请先转换。手机上传必须通过 Windows 专用/域网络检查；HTTP 不是加密传输，只能用于可信局域网。程序不修改系统网络/防火墙设置。

## Windows 桌面版

本机已经验证以下最小工具链，不需要完整 Visual Studio IDE：

- Visual Studio Code
- Rust stable x86_64-pc-windows-msvc
- Microsoft Visual Studio 2022 Build Tools（VCTools workload）
- Windows SDK 10.0.26100.0
- WebView2 Runtime

安装工具链后执行：

```powershell
npm run tauri dev
npm run tauri build
```

生产构建输出 MSI 与 NSIS 安装包。应用本体不捆绑本地大模型。

最新的安装包、哈希、内存口径和安装/卸载验证见 [BUILD_REPORT.md](./BUILD_REPORT.md)。

## 数据安全

- 正式数据只由用户确认写入。
- 手机上传会话随机、短时、仅允许私有 IPv4 局域网。
- 外部助手不得直接访问 SQLite。
- 前端没有直接执行 SQL 的权限；初始化后不能用完整前端快照覆盖领域仓库。
- AI API Key 只进入 Windows Credential Manager，不写入 SQLite 或 JSON 导出。
- 忘记备份口令后无法解密，应用不会保存或找回口令。
- 不把未知营养值当作零。
- 同日体重修订保留原记录和审计链，不静默覆盖。
- 运动消耗不抵扣饮食目标。
- 本产品不是医疗器械，不提供诊断或治疗建议。
