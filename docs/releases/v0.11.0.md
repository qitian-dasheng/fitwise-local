# 轻衡 0.11.0 发布记录

**日期**：2026-10-26 · **分支**：`dev/0.9.4`（工作分支；0.11.0 提交在 main）· **基线**：v0.10.0（main）
**性质**：**大功能版（次版本 0.10→0.11）**——原 0.10.1（更新器三件套）与原 0.12.0（AI 采集）按用户决定并入本版。零 SQL 迁移（`user_version` 仍 14）。

## 本版内容

### 1. 内置食材目录（权威数据，禁止 AI 估算）

- **数据**：USDA FoodData Central SR Legacy（公有领域全量包）采集 **235 项**八大类常见食材（主食谷物/蛋奶/畜禽肉/水产/豆制品/蔬菜/水果/油脂调味，每类 26–35 项），每 100 克可食部口径；**每条带 sourceRef（库名+FDC ID+英文原名）注记，数值全部来自数据原文，缺失标 unknown，不做任何推算**。构建管线 `scripts/build-food-catalog/`（可复跑审计）；后续按人工收录制扩充（用户导出发维护者审核）。
- **启动幂等合并**：按目录版本号只合并一次；用户改过的条目不覆盖；删除登记墓碑单例（升级不复活）；合并失败不阻塞启动。
- **UI**：食材库「全部」分组个人食材在前、内置目录在后（分组头+「内置」徽标）；**修改目录食材=生成个人副本**（可改名，原条目保留）；收藏/归档/删除/食物柜/记餐选择器全兼容。

### 2. AI 采集通道 v1（本地 Ollama，默认关闭）

- 设置 → AI 采集：Ollama 地址（默认 localhost:11434）+ 连接测试 + 模型选择 + 总开关（**默认关**）。
- 饮食页「AI 描述」（开启后显示）：一句话描述 → Ollama（JSON 约束输出，Rust 严格校验+120s 超时）→ **可编辑草稿**（名称/营养行内改）→ 全部加入待确认篮子 → BasketBar 人工核对确认。
- **边界**：营养值一律 `ai_estimate`/low（模型估算，仅供参考），永不直接入账；草稿不持久化（关窗即弃）；解析失败展示错误不静默。
- **隐私**：AI 只连接本机 Ollama，**无任何外网请求**；外网仍仅更新检查。

### 3. 更新器网络三件套（原 0.10.1 并入，v0.10.0 验签失败根因修复）

- **代理跟随**：新增 `get_system_proxy` 命令（winreg 读 WinINET 注册表，唯一新依赖）；偏好「跟随系统代理（默认）/直连」；手动与静默检查同源传 `check({proxy})`。
- **失败一次性提示**：静默检查失败记入偏好，今日页页头细提示条（可关闭，下次失败重现）。
- **错误详情**：检查更新失败展示完整错误+一键复制。

### 4. 镜像后备端点

更新端点在官方 GitHub 后追加 ghfast 社区加速镜像（官方失败按序尝试；minisign 验签保护下载完整性，镜像只能影响可用性不能篡改内容）。镜像实测 200。

## 技术要点

- 新依赖：`winreg`（注册表，零传递）、`reqwest` blocking+json（Ollama HTTP；Tauri 栈已有 reqwest）。`Cargo.toml` 汇总声明。
- `catalogTombstones` 登记为第二单例（SINGLETONS），读写路径对旧信封全兼容（缺失补空数组，读写测试覆盖）。
- 目录合并 hook 挂 `open_database`（仓库就绪才合并；未初始化新库等首次命令建库）。
- **AI 思考型模型适配（实机验收拦截）**：qwen3.x 等思考型模型默认先输出上千字 `thinking`，既慢又会吃掉 `num_predict` 预算，导致正文为空或被截断（实测 qwen3.5-4b-32k：开思考 28.7 秒且正文空，关思考 **0.4 秒**、thinking 0 字符、三条全部输出；gemma4-e2b 亦正常 11.9 秒）。请求体加 `"think": false`，并对结构化抽取用 `temperature: 0` + `num_predict: 2048` + `keep_alive: 30m`（模型驻留，重试不必重新加载）；仅当服务端返回 **400**（参数不被接受）时去掉 `think` 重试一次，5xx 直接报错并提示"模型可能未能加载"。提示词同时改为强制逐项拆分并给出三食物示例，修正"一句话只出 1 条"的问题。
  - 实测记录：`qwen3.6:35b-a3b-q4_K_M` 在本机**无论是否带 think 参数都返回 500**（33–38 秒后失败），属该模型未能加载（内存/量化），非本应用缺陷；验收请用 `qwen3.5:4b` / `qwen3.5:9b` / `gemma4:e2b`。
- **来源出处透传修复**：合并时 `sourceRef`（库名 + FDC 编号 + 英文原名）**根本没写进库**，前端拿不到任何来源数据，"来源见悬浮"是空话。现写入 definition 并在搜索投影中显式保留，前端在名称与「内置」徽标上挂 `title` 悬浮；`catalogVersion` 升到 **3**，合并时按 catalogId 回填已存在条目的 sourceRef。
- **内置标记透传修复**：`search_state` 会把定义反序列化成 `Definition` 再序列化返回，而结构体未声明 `catalogId` / `category` → 字段被 serde 静默丢弃，导致「内置」徽标不显示、个人/内置分组失效（看起来"数据有了但分不清来源"）。已补两个 `Option` 字段（`default`，兼容旧数据），并加搜索投影守卫测试。
- **搜索硬截断修复**：`results.truncate(100)` 会把 235 项目录的「全部」视图截到 100 条，用户既看不到全量也察觉不到缺失。上限改为 1000（仅作防御）。
- **AI 命令阻塞主线程修复**：`ollama_draft` / `ollama_list_models` 原为同步 Tauri 命令 + `reqwest::blocking`（最长 120 秒），同步命令跑在主线程 → 窗口直接「未响应」。改为 `async` + `tauri::async_runtime::spawn_blocking`，主线程只等结果。
- **目录 basis 形状修复（实机验收拦截）**：Rust 侧 `Basis` 是 `deny_unknown_fields`，只接受 `quantity`/`unit`；而目录生成器把 `measurementBasis` 也写进了 `basis`（它本属于 `definition` 层），导致食材库整页报 `unknown field measurementBasis, expected quantity or unit`。修法：生成器移除该字段并在构建期断言形状；`catalogVersion` 升到 **2**，合并时对已存在的版本原地清理非法 basis 字段（幂等跳过不会重写旧条目，只能靠这步修复）。此前 70 项版本同样带此缺陷，属既有 bug 而非本次引入。
- **能量单位修复（发布前拦截）**：USDA 每条食物同时给出 `Energy`（kcal）与 `Energy`（kJ）两条营养，早期提取只按名称匹配、循环内后写覆盖前写，导致约半数条目把 kJ 数值标成 kcal（虚高约 4.18 倍，例如鸡蛋 599 而非 143）。改为按 `nutrient.unitName` 精确锁定 kcal，只有 kJ 的条目宁可标 unknown 也不换算；`build-catalog.mjs` 增加能量守卫（已知条目区间 + 非油脂上限），构建期即失败。
- **更新清单签名错配修复**：`make-update-manifest.mjs` 早期用 `readdirSync().find(...)` 取 nsis 目录里第一个 `*-setup.exe`，而该目录累积了 0.9.2–0.11.0 多代产物，导致 `latest.json` 内嵌的是 **0.9.3 的签名**（照原样发布会让所有 0.10.0 用户验签失败）。改为按版本号精确匹配 + 唯一性断言，并解码 `.sig` 的 trusted comment 校验 `version:` 与文件名。
